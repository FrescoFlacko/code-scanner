Profile transformation before/after analysis

Completed July 11, 2026.

Method: each repository was scanned before any profile changes using the legacy 283-rule configuration. After implementation, the same roots were scanned in JSON mode: the two React/Next repositories used the default generic profile, and the Angular repository used explicit generic + angular. JSON mode avoided writing history into the target repositories.

Interpretation

  • Signal-to-noise improved materially: the dominant findings were measurement probes and universal policy rules, not actionable defects.
  • Metrics were preserved: cognitive and cyclomatic values stayed stable, so trend/scoring inputs remain available.
  • Angular coverage improved: template discovery and accessibility rules found issues the legacy JS/TS-only scan could not see.
  • Security semantics are more honest: noisy hotspots such as dynamic property access and non-literal paths are not labeled vulnerabilities by default. Lambda and stricter review can opt into broader security coverage.
  • Artifacts became smaller: approximately 1.70 MB → 91 KB, 115 KB → 13 KB, and 270 KB → 22 KB.

Calibration warning: the large reduction is desirable given the legacy noise, but profiles should remain advisory until their findings are reviewed. The Angular profile now has positive fixtures for sanitization bypass, floating promises, unused variables, generated-code isolation, and template defects; the real repository currently contains no detected Angular security hotspot.

Recommended next calibration

  1. Review the 59 remaining findings across these repositories and label true positive, acceptable pattern, or false positive.
  2. Create positive fixtures for security defects the generic and Lambda profiles must detect.
  3. Run the Lambda profile against at least one real Lambda repository; none of the three requested roots declares a Lambda stack.
  4. Decide whether no-nested-conditional belongs in generic or strict—it represents 43 of the remaining generic findings.
  5. Keep CI gating limited to scanner errors and reviewed high-confidence correctness/security rules until the corpus is calibrated.
