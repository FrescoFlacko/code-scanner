General JS/TS profile

Portable correctness, maintainability, security, and cleanliness coverage for mixed JavaScript and TypeScript repositories.

8/10

Outcome

Correctness

ESLint's recommended rules are always active, catching undefined identifiers, unreachable code, invalid control flow, duplicate declarations, and related defects.

TypeScript

Recommended non-type-aware TypeScript rules are portable by default. The opt-in typed profile adds promise and unsafe-value analysis where a project service is available.

Environments

node and browser add accurate runtime globals. This avoids both false positives and the unsafe assumption that every global exists everywhere.

Framework

The opt-in react profile uses the official React Hooks recommended rules. Angular and Lambda retain their specialized 8/10 profiles.

Why this is 8/10

  • Broad, defensible correctness coverage now applies to JS, JSX, TS, TSX, MJS, CJS, MTS, and CTS.
  • Runtime and framework assumptions are explicit and composable instead of being guessed.
  • Generated sources are suppressed; tests and tooling configs use a lighter scope, preventing type-project failures.
  • The high-volume no-explicit-any policy is disabled in the portable baseline and remains available as an override.
  • Rule inventories and dependency versions are locked by tests to make upgrades visible.
Remaining gap to 9/10: repository-aware overrides for mixed server/client boundaries, first-class Vue/Svelte/Next profiles, import-resolution and dependency-boundary analysis, and a measured false-positive budget across a larger corpus. Those improvements require product policy and ecosystem-specific calibration, not simply enabling more rules.

Verification

Automated coverage includes generic JS correctness, TS cleanliness, Node/browser globals, React Hooks, typed promises, generated files, Angular, Lambda, history behavior, configuration validation, operational failures, and manifest drift. The completed suite contains 158 passing tests.
